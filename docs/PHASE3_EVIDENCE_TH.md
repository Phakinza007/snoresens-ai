### ตารางโมเดลกรน — ผลเดิมที่บันทึกไว้

| โมเดล | Input features | Accuracy | Precision กรน | Recall กรน | F1 กรน | AUC | Threshold |
|---|---|---:|---:|---:|---:|---:|---:|
| Embedding head | YAMNet embeddings 1,024 ค่า | 100.00% | 100.00% | 100.00% | 100.00% | 1.000 | 0.36 |
| Score head ที่เว็บใช้ | YAMNet class scores 521 ค่า | 97.99% | 100.00% | 96.00% | 97.96% | 1.000 | 0.63 |

ทั้งสองรายงานระบุ train 693 / validation 149 / test 149, test class 0 ไม่กรน 74 คลิป และ class 1 กรน 75 คลิป ค่า AUC 1.0 ของ score head อยู่ร่วมกับ accuracy 97.99% ได้ เพราะ AUC วัดลำดับคะแนนหลาย threshold ส่วน confusion matrix ใช้ threshold ที่เลือกไว้ที่ 0.63

คะแนนนี้เป็นผลเก่า ไม่ได้ประเมินกรนใหม่ในรอบนี้ ไม่มี original test manifest จึงยังตรวจยืนยันไม่ได้ว่าเป็นคลิปชุดเดียวกันทุกไฟล์ระหว่างสองโมเดล ห้ามสรุปว่าความต่างนี้เป็น improvement หลัง Phase 2 และห้ามนำคะแนน 100% ไปอ้างเป็นคะแนนของโมเดลที่เว็บเรียก

ยังไม่สร้าง ROC ของโมเดลกรน เพราะไม่มีคะแนนทำนายรายตัวอย่างของชุดทดสอบเดิม การมีค่า AUC อย่างเดียวไม่พอสร้างเส้น ROC

## 2. ข้อมูลครบพอประเมินใหม่หรือไม่

### กรน: ยังไม่ครบสำหรับทำซ้ำผลเดิม

- มี YAMNet base, embedding head, score head แบบ Keras/TFLite และ metrics เดิม
- ไม่พบ dataset กรน 991 คลิปในโฟลเดอร์โปรเจกต์หรือ cache/ตำแหน่งไฟล์ทั่วไปที่ค้นในรอบนี้; พบเสียงเดโมซึ่งใช้แทนชุดทดสอบไม่ได้
- ไม่มี `artifacts/test_files.json` หรือรายชื่อ/hash คลิปใน original split ให้เทียบ
- `train.py` ปัจจุบันมี seed 42, การลบข้อมูลซ้ำ และวิธีแบ่ง 70/15/15 แต่ seed อย่างเดียวไม่ยืนยันลำดับไฟล์หรือรุ่น dataset เดิม และ schema ของ `metrics.json` เดิมต่างจากที่สคริปต์ปัจจุบันสร้าง
- ถ้าจะกู้การประเมินเดิม ต้องหา dataset รุ่นที่ใช้จริงพร้อม original split/บันทึกการทดลองก่อน ไม่ใช้การดาวน์โหลดชุดปัจจุบันและสุ่มใหม่แล้วเรียกว่า original test

### ไอ: มีข้อมูลและรันประเมินซ้ำแล้ว

ข้อมูล Coswara 186 ไฟล์ / 32 คน มี quality labels และรายชื่อ test เดิมครบ วิธีแบ่งปัจจุบันสร้างรายชื่อ test ได้ตรงกับที่บันทึกทั้ง 42 ไฟล์ โดย train/validation/test แยกบุคคลกัน

| Split | ไม่ไอ: หายใจ/นับเลข | ไอ | รวมไฟล์ | จำนวนคน |
|---|---:|---:|---:|---:|
| Train | 68 | 36 | 104 | 18 |
| Validation | 26 | 14 | 40 | 7 |
| Test | 28 | 14 | 42 | 7 |

ใช้ `cough_score_head.tflite` เดิม, preprocessing เดิมที่เลือกหน้าต่าง 1 วินาทีดังที่สุด และ threshold 0.51 เดิม ไม่ฝึกหรือเลือก threshold ใหม่จาก test

- Accuracy **92.86% (39/42)**; confusion matrix **[[27, 1], [2, 12]]** ตรงผลเดิม
- Precision ไอ **92.31%**, recall ไอ **85.71%**, F1 ไอ **88.89%**, ROC AUC ใหม่ **0.9541**
- เก็บความน่าจะเป็นและ SHA-256 ของไฟล์เสียงที่ใช้ทุกรายการใน `results/phase3-evidence/cough-test-predictions.csv`
- ไม่มี hash ต้นฉบับจากวันฝึกเดิม จึงยืนยันได้ว่ารายชื่อไฟล์ตรงและผลซ้ำได้กับไฟล์ปัจจุบัน แต่ไม่อ้างว่าพิสูจน์ว่าเนื้อหาเสียงไม่เคยเปลี่ยนตั้งแต่วันฝึก
- งานนี้เป็น prompted cough vs breathing/counting ไม่ใช่การตรวจไอในห้องนอนหรือการเปรียบเทียบความเก่งกับโมเดลกรน

ข้อมูลการตรวจทั้งหมดอยู่ใน `results/phase3-evidence/data-audit.json`, `cough-reevaluation.json` และ `cough-split-manifest.json` ตรวจ hash แล้วไฟล์ใน `artifacts/` ไม่เปลี่ยนจากก่อนรันสคริปต์

## 3. หน้าเว็บและไฟล์ export

ตรวจด้วย headless Google Chrome และ local HTTP server จริง ใช้ WAV เดโม 45 วินาทีและเสียงเงียบ 6 วินาที มี **28 checks ผ่านทั้งหมด** ไม่ใช้ผลจำลองแทน API ใน flow นี้

| กลุ่ม | สิ่งที่ตรวจและผล |
|---|---|
| เริ่มต้น | ผลลัพธ์ยังซ่อน; ตัวเลือกโมเดลวิจัยที่ยังไม่ฝึกถูกปิดใช้งาน |
| อัปโหลด | รับ WAV จริงและแสดงผล; เดโม 45 วินาทีมี timeline 45 รายการและกรน 28 วินาที |
| Timeline / playback | metadata ความยาว 45 วินาที, เลื่อนเวลาได้, กดเหตุการณ์แล้ว seek ได้, เล่นเสียงแล้วเวลาขยับ, กรองกรนได้ |
| กราฟ | ขยายส่วน Spectrogram และกราฟประกอบได้; ตรวจภาพหน้าจอผลจริงแล้ว |
| เปรียบเทียบ | เพิ่มสองไฟล์และเลือก reference baseline ได้ |
| JSON รายไฟล์ | summary และ timeline ตรงกับ API, มีสูตรคะแนนเพิ่มเติม, ไม่มี browser-only `sourceUrl`/`id` |
| JSON ทั้งหมด | มีผลสองไฟล์ครบ; summary ตรงกับผลวิเคราะห์ |
| Timeline CSV | ครบ 45 แถว, เวลา/label/probability ตรงกับ API และค่า loudness ที่ไม่มีค่าคงเป็นช่องว่าง |
| Comparison CSV | เวลา สัดส่วนกรน และ combined score ตรงกับ JSON; ค่า unavailable คงว่าง |
| Breathing CSV | จำนวนหน้าต่างและสถานะตรงกับ API; ไม่เติมค่าอัตราหายใจเมื่อประเมินไม่ได้ |
| Error states | fake WAV แสดงข้อผิดพลาดโดยผลเก่ายังอยู่; นามสกุลอื่นถูกข้าม |
| จอแคบ | viewport 390 × 844 ไม่มีการล้นแนวนอนทั้งหน้า ตารางกว้างอยู่ในกรอบเลื่อนของตัวเอง |
| ลบผล | ลบทีละรายการและกลับสู่สถานะเริ่มต้นได้; ไม่พบ uncaught JavaScript errors |

ไฟล์ที่ดาวน์โหลดจริง ภาพหน้าจอ และรายการตรวจรายข้ออยู่ใน `results/phase3-evidence/browser/`

ขอบเขตการตรวจ: playback ตรวจสถานะเล่นและเวลาที่ขยับ ไม่ใช่การฟังยืนยันด้วยคน; viewport มือถือเป็น Chrome จำลองขนาดจอ ไม่ใช่การทดสอบโทรศัพท์จริง; ยังไม่ตรวจไมโครโฟน/การอัดต่อเนื่อง/ล็อกจอ/การทำงานจริง 8 ชั่วโมง การรวมเซสชันจากไฟล์อัดหลายส่วนยังไม่ได้กดตรวจผ่านหน้าเว็บในรอบนี้

## รันซ้ำ

```sh
.venv/bin/python docs/prepare_phase3_evidence.py
.venv/bin/python docs/check_phase3_browser.py
```
