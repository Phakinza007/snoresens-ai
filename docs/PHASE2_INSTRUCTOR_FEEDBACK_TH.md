- `artifacts/mobile_metrics.json`: โมเดลกรนแบบ YAMNet scores/TFLite, test 149 คลิป, accuracy 97.99%, confusion matrix `[[74, 0], [3, 72]]`, threshold 0.63
- ทั้งสองผลใช้ dataset กรน 991 คลิป แบ่ง train 693 / validation 149 / test 149 เป็น random clip split ไม่มี person/recording IDs จึงยังยืนยันผลข้ามคนหรือห้องนอนจริงไม่ได้
- สองโมเดลนี้เป็นคนละรูปแบบ feature ไม่ใช่หลักฐานก่อน–หลังรับ feedback โดยอัตโนมัติ ต้องตรวจการทดลองก่อนอ้าง improvement
- `artifacts/cough_metrics.json`: งานเสียงไอแยกต่างหาก ไม่ใช่ตัวเปรียบเทียบ improvement ของงานกรน
- `results/test_snore_summary.json`: มีผลตัวอย่างยาว 150.435 วินาที ตรวจพบ 19 ช่วง แต่ยังต้องเตรียมและตรวจเสียงเดโมสั้นตามคำแนะนำ
- `docs/SANOR_PROJECT_REVIEW_TH.md`: รายงานว่ามีเว็บ timeline, playback, กราฟ, export และเปรียบเทียบไฟล์แล้ว แต่ยังต้องตรวจ flow จริงอีกครั้งหลังย้ายโฟลเดอร์

## ลำดับงานต่อไป

1. ตรวจเว็บด้วยเสียงจริงให้ครบ flow หลัก และระบุว่าโมเดลใดใช้ในเดโม
2. เตรียมเสียงเดโม 30–60 วินาทีพร้อมป้ายเวลาที่ตรวจด้วยคน มีช่วงกรนและไม่กรน
3. ทดสอบกรน ไม่กรน เสียงรบกวน เสียงผสม และไฟล์ผิดรูปแบบ เก็บ expected/actual/pass/fail และข้อจำกัด; กรณีรูมเมทเป็นการทดลองเพิ่มเติม
4. ทำตารางเปรียบเทียบโมเดลจากผลที่ตรวจสอบได้ หากไม่มีหลักฐานก่อน–หลัง ให้รายงานการเปรียบเทียบตามจริงโดยไม่อ้างว่าดีขึ้นหลัง Phase 2
5. จัดสไลด์สรุปและซ้อมเดโมรวม 8 นาที โดยให้เวลาส่วนใหญ่กับการสาธิตระบบ
