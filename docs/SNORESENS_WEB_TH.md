# Snoresens AI — เว็บจากต้นแบบ Figma

ทำวันที่ 14 พฤศจิกายน 2026 จาก design/prototype ที่ผู้ใช้ส่งมา โดยเชื่อมระบบวิเคราะห์เสียงเดิม

## เปิดใช้งาน

ดับเบิลคลิก `เปิดเว็บ Sanor.command` หรือรันจากโฟลเดอร์โปรเจกต์:

```sh
.venv/bin/python web_server.py
```

- เว็บใหม่: http://127.0.0.1:8765/
- เครื่องมือวิเคราะห์ละเอียดเดิม: http://127.0.0.1:8765/lab
- เซิร์ฟเวอร์ยังทำงานเฉพาะเครื่องนี้ การรองรับหน้าจอมือถือหมายถึง responsive layout ไม่ใช่เปิดให้โทรศัพท์เครื่องอื่นเข้าถึงแล้ว

## สิ่งที่ใช้ได้

- หน้าหลักโทนขาว/น้ำเงินตามต้นแบบ พร้อมเริ่มบันทึก อัปโหลด WAV และลองเสียงตัวอย่างจริง
- หน้าเตรียมก่อนบันทึกและหน้ายินยอม ก่อนขอสิทธิ์ไมโครโฟน
- บันทึก PCM mono 16 kHz ผ่าน AudioWorklet รวมช่วงเงียบ แบ่งเป็นส่วนละ 30 นาทีโดยประมวลผลแต่ละส่วนแยกกัน ตัวจับเวลาอ้างอิงจำนวน sample ที่รับได้
- หน้าบันทึกโทนน้ำเงินเข้มตามต้นแบบ มีพัก/บันทึกต่อ โดยไม่นับช่วงพักในเวลาเสียงที่บันทึก กราฟบนหน้านี้อ้างอิง RMS จากเสียงที่รับจริง
- หยุดบันทึกแล้วแสดงรายงานจาก `/api/analyze` เดิม โดยไม่เปลี่ยนโมเดลหรือ threshold
- รายงานมีเวลาบันทึก เวลากรน สัดส่วนกรน เหตุการณ์ กราฟ timeline, playback, seek, รายละเอียดการวัด และดาวน์โหลด JSON / timeline CSV / WAV
- ประวัติเก็บทั้งเสียงและผลใน IndexedDB ของเบราว์เซอร์เดียวกัน เปิดดูและย้อนฟังหลัง reload ได้ มีกราฟรายการล่าสุดและ export JSON/CSV รวม
- โปรไฟล์แก้ชื่อที่แสดงได้ พร้อมคำอธิบายความเป็นส่วนตัว การวัด และการจัดวางอุปกรณ์
- ลบรายงานทีละรายการหรือทั้งหมดผ่านหน้าต่างยืนยัน; การลบไม่ลบไฟล์ต้นฉบับ/ไฟล์ที่เคยดาวน์โหลด
- มือถือใช้ bottom navigation; เดสก์ท็อปมี sidebar และ layout สองคอลัมน์

## การนำต้นแบบมาทำงานจริง

- คงหน้าตาและ flow หลักจาก Figma: home `3:130`, prepare `3:392`, consent `3:463`, report `4:359`, history `4:841`, profile `5:694`
- ต้นแบบมีข้อมูลจำลองและป้ายความเสี่ยง เว็บจริงไม่สร้างคืนย้อนหลังหรือป้ายความเสี่ยงทางการแพทย์จากข้อมูลเสียงที่ยังไม่ได้ยืนยัน จะแสดงสัดส่วนกรนและค่าที่ระบบวัดได้
- รายงานเดิมมีเกณฑ์คะแนนรวมของโครงการอยู่แล้ว เก็บไว้ในรายละเอียด/JSON พร้อมคำอธิบายว่าเป็นเกณฑ์ทดลอง ไม่ใช่ความเสี่ยงโรค
- ไม่แบ่งสัดส่วนหายใจ/เงียบ/อื่นให้รวมเป็น 100% จาก review scores ที่ซ้อนทับกันได้ ใช้กรนกับไม่พบกรนในกราฟสัดส่วนหลัก
- ไม่มีการแสดงนาฬิกาหรือแถบสถานะโทรศัพท์จำลองในเว็บ
- Figma MCP ยังปฏิเสธสิทธิ์เข้าถึงเลเยอร์ จึงเทียบจากภาพ prototype ใน browser รายละเอียดฟอนต์/เวกเตอร์บางส่วนเป็นการสร้างตามภาพและใช้ Lucide แทน ไม่อ้างว่าถอดเลเยอร์ตรงทุกพิกเซล ดู `web/snoresens/CREDITS.md`

## ข้อมูลในเครื่อง

เสียงและผลเก็บใน IndexedDB ชื่อ `snoresens-local` แยกตาม origin ของเว็บ ชื่อที่แสดงเก็บใน localStorage ผู้ใช้โปรไฟล์เบราว์เซอร์เดียวกันอาจเปิดดูได้ การล้างข้อมูลเว็บไซต์จะลบประวัติ แนะนำดาวน์โหลดผลที่ต้องการเก็บ

หากบันทึก IndexedDB ไม่สำเร็จ เว็บแจ้งให้ดาวน์โหลดผลก่อนปิดแท็บ ผลนั้นอาจยังดูได้เฉพาะในหน่วยความจำของแท็บ

เซิร์ฟเวอร์ใช้ไฟล์ชั่วคราวในการวิเคราะห์แล้วลบตามพฤติกรรมเดิม ไม่มีการส่งเสียงไปบริการวิเคราะห์ภายนอก แต่ข้อมูลที่ดาวน์โหลดจะอยู่บนเครื่องจนผู้ใช้ลบเอง

## การทดสอบและหลักฐาน

ผลรอบส่งมอบ: เว็บใหม่ **46/46 checks**, หน้าเดิม `/lab` **28/28 checks**, Python **47 tests** และ Node **7 tests** ผ่านทั้งหมด

- ผล browser checks รายข้อและ screenshots: `results/snoresens-web-checks/`
- ทดสอบ Chrome จริงกับ local API และไฟล์เสียงจริง: upload, report, playback, export, reload persistence, history, deletion, invalid WAV และ sample
- ทดสอบไมโครโฟนด้วยอุปกรณ์จำลองของ Chrome: consent → start → PCM capture → stop → WAV inference → report
- ทดสอบแบ่งส่วนโดยลดระยะส่วนสำหรับการตรวจ แล้วตรวจว่าทุกส่วนเป็น mono 16 kHz, ลำดับส่วนครบ และผลรวมระยะเสียงตรงกับตัวจับเวลาจาก samples
- ตรวจภาพที่มือถือ 390 × 844 และเดสก์ท็อป 1440 × 1000; กดดูทั้งหน้าเดิมที่ `/lab` และหน้าใหม่
- ชุดทดสอบ Python เดิม, Node เดิม และ WAV encoding boundary tests

ยังไม่ได้ยืนยันกับไมโครโฟนจริง การอัดข้ามคืน การล็อกจอ การพักเครื่อง โทรศัพท์จริง หรือประสิทธิภาพในห้องนอนจริง ข้อมูลเสียงจริงที่ทดสอบไม่มีป้ายกรนจากคนครบทุกวินาที จึงไม่ได้ใช้การผ่าน flow เป็นคะแนน accuracy ใหม่

```sh
.venv/bin/python -m unittest discover -s tests -v
node --test tests/test_app_audio.mjs tests/test_audio_charts.cjs tests/test_research_scores.cjs tests/test_sleep_audio_web.cjs tests/test_snore_score.cjs tests/test_web_measurements.cjs
.venv/bin/python docs/check_snoresens_app.py
.venv/bin/python docs/check_phase3_browser.py
```

Browser checks ใช้โปรไฟล์ Chrome แยกและพอร์ตชั่วคราว จึงไม่แก้ประวัติจริงบนพอร์ต 8765 ของผู้ใช้
